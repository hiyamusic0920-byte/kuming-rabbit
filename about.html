About

一個 QA、兩個 AI agent、十五話翻車紀錄

這個網站不是教學，也不是工具介紹。它記錄的是我把 AI agent 放進真實 QA 工作流程之後，實際發生了什麼。

誰在寫

Sunny · QA Engineer

  • 本業

    在 OwlTing 做 QA，負責旅宿管理系統與訂房系統。角色實際上偏 QA 與 PM 之間：要測，也要盯需求講清楚了沒有。

  • 為什麼開始弄這個

    起點很不偉大：整理測試證據和寫報告太花時間，我想偷懶。第一次真的做出「輸入一張票、產出報告」的時候我很興奮，然後打開報告發現整個理解都是錯的。這個網站從那裡開始。

    那一話：第 02 話

  • 報告格式為什麼那麼講究

    因為交出去的東西要能過稽核。這決定了整套流程的形狀：交付物必須固定、證據必須可追溯、結論必須有人簽字。不是為了好看。

這個網站自己怎麼做的

沒有框架，沒有 build step，18 頁漫畫由腳本產生。

  • 技術很土，刻意的

    靜態 HTML 加一份 CSS，放在 GitHub Pages。漫畫頁由 Python 腳本從圖片目錄產生，所以改版只要改腳本，不用手動改 18 個檔案。

  • 漫畫本體有保護機制

    重產漫畫頁之前會先做一次比對：標題、格數、圖檔路徑、alt 文字、故事文字、話數順序、前後話連結。外殼可以改，漫畫本體不准變。這條規則的來歷跟站上寫的那些一樣——是撞出來的。

  • 角色對照

    漫畫裡的苦命兔是 Claude Code，苦力怕是 Codex，家規是共用規則檔，秘密小本本是知識層。完整對照表在秘密基地那頁。
